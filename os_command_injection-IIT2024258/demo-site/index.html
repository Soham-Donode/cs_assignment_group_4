Root Cause
Why it works: child_process.exec() internally calls cmd.exe /d /s /c "<user_input>" on Windows. Any shell meta-characters (&, |, &&) embedded in the input are interpreted by cmd.exe as command separators — not as ping arguments — so arbitrary commands execute at the same privilege level as the Node.js process.

exec() vs. execFile() — Why It Matters
Aspect Vulnerable — exec() Secure — execFile()
Shell invoked? Yes — cmd.exe /d /s /c "..." No — binary spawned directly
User input handling Concatenated into a shell command string Passed as a discrete array element (argv)
Meta-chars & | && Evaluated by cmd.exe as command separators Treated as literal text by ping.exe
Input validation None Allowlist regex — alphanumeric, dot, hyphen only
Payload 127.0.0.1 & whoami Executes both ping and whoami Rejected at input validation, code never runs
